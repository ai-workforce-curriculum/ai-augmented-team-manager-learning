# mod-111 — Vendor Selection, Tool Budget, and Build-vs-Buy at Team Scope

**Estimated effort:** 12 hours.

## What this module does

Turns the AI-tool landscape into **a defensible, dated, team-scope decision**: which copilots and agent frameworks the team runs, how seats and tokens are distributed, and what procurement / security / legal evidence is on file for each vendor. The decision is made against a team-shaped build-vs-buy matrix — not a generic one — and is re-evaluated on a stated cadence rather than left as a one-time choice the team drifts away from.

The module treats *vendor selection* and *tool budget* as the same artifact: the tool registry. Every entry has an evaluation rationale, a vendor-due-diligence record ([Data Processing Addendum](https://gdpr-info.eu/art-28-gdpr/), [SOC 2](https://www.aicpa-cima.com/topic/audit-assurance/audit-and-assurance-greater-than-soc-2) posture, model-provenance clause, exit plan), a seat and token allocation aligned with [`mod-105`](../mod-105-team-ai-enablement-programs/)'s stage ladder, and a sunset condition. The module's five pieces — the [copilot evaluation matrix](01-the-vendor-selection-problem-at-team-scope.md), the [build-vs-buy matrix](03-build-vs-buy-matrix-at-team-scope.md), the [agent-framework matrix](04-agent-frameworks-and-authoring-environments.md), the [budget-distribution rubric](05-tool-and-token-budget-distribution.md), the [due-diligence checklist](06-vendor-due-diligence-and-data-handling.md) — compose into a single tool registry under one owner (you).

This module is **not** a procurement course — bulk negotiation, enterprise framework ownership, and multi-year commitment architecture live upstream at [`ai-enablement-lead`](https://github.com/ai-workforce-curriculum/ai-enablement-lead-learning) (level 45). It is **not** a vendor-security-assessment course — penetration testing, red-teaming, and attack-surface analysis belong to SecOps. It is **not** a FinOps course — GPU reservations, long-term commitment pricing, and hosting-cost architecture belong to the FinOps function. The manager-scope deliverable is the *team's* tool registry and the evidence that each entry on it is a deliberate, dated, revocable choice.

## Learning objectives

- Evaluate AI coding / knowledge-work copilots — [Cursor](https://www.cursor.com/), [GitHub Copilot](https://github.com/features/copilot), [Claude Code](https://docs.claude.com/en/docs/claude-code), [Windsurf](https://windsurf.com/), [Continue](https://docs.continue.dev/), [Sourcegraph Cody](https://sourcegraph.com/docs/cody), [Zed](https://zed.dev/docs/ai), [JetBrains AI Assistant](https://www.jetbrains.com/ai/) — against team context on latency, output quality, cost per seat, data handling, and extensibility, and produce a defensible build-vs-buy matrix at team scope.
- Evaluate agent frameworks — [LangChain / LangGraph](https://langchain-ai.github.io/langgraph/), [CrewAI](https://docs.crewai.com/), [AutoGen](https://microsoft.github.io/autogen/), [PydanticAI](https://ai.pydantic.dev/) — and agent-authoring environments — [Claude Code](https://docs.claude.com/en/docs/claude-code), [Cursor](https://docs.cursor.com/), [Codex](https://github.com/openai/codex) — at team scope, including whether to standardise or let ICs pick.
- Distribute tool budgets — seat budgets, token budgets, enterprise commitments — in a way that aligns with [`mod-105`](../mod-105-team-ai-enablement-programs/)'s enablement stages, not seniority.
- Partner with procurement, security, and legal for vendor due-diligence; capture [DPA](https://gdpr-info.eu/art-28-gdpr/) clauses, [SOC 2](https://www.aicpa-cima.com/topic/audit-assurance/audit-and-assurance-greater-than-soc-2) posture, and model-provenance guarantees in a shape the upward-rolling program consumes.
- Position the ownership boundary: org-wide procurement and enterprise framework ownership live at [`ai-enablement-lead`](https://github.com/ai-workforce-curriculum/ai-enablement-lead-learning) (L45); this module covers team-scope selection, ongoing evaluation, and the manager's half of the procurement partnership.

## Where this fits in the track

mod-111 sits between the *governance operational posture* in [`mod-110`](../mod-110-ai-governance-and-policy-at-team-scope/) and the *ritual calendar* that carries the ongoing cadence in [`mod-112`](../mod-112-cross-functional-leadership-and-ritual-calendar/). It is the module where vendor and tool decisions become evidence-shaped rather than preference-shaped.

- **Back-links.** [`mod-101` Ch. 5](../mod-101-ai-augmented-team-manager-position-and-contract/) C5 data-handling clause sets the data position that filters vendor options here; [`mod-102`](../mod-102-team-ai-adoption-and-roadmap/) adoption roadmap is where the demand signal for a new tool originates; [`mod-104` Ch. 2](../mod-104-productivity-measurement-and-ai-roi/) AI-cost tile consumes the budget distribution this module sets; [`mod-105` Ch. 4](../mod-105-team-ai-enablement-programs/04-tool-budgets-by-learning-stage.md) is the stage ladder this module's budget distribution follows; [`mod-106`](../mod-106-workflow-redesign-and-agent-delegation/) tool-authorisation policy is the operational filter composed with this module's registry; [`mod-110` Ch. 6](../mod-110-ai-governance-and-policy-at-team-scope/06-data-ip-and-confidentiality-practice.md) data-IP-confidentiality policy is where the vendor clause reader is maintained; this module reads from it rather than duplicating.
- **Forward links.** [`mod-112`](../mod-112-cross-functional-leadership-and-ritual-calendar/) carries the quarterly tool-registry review on the ritual calendar; the upward tool-registry rollup is a section of the quarterly packet from [`mod-110` Ch. 7](../mod-110-ai-governance-and-policy-at-team-scope/07-upward-evidence-packet-and-ownership-boundary.md).
- **Sideways links.** SecOps owns vendor security assessment depth; procurement owns negotiation and signature; legal / privacy office owns clause interpretation; FinOps owns long-term commitment architecture. The manager partners with each through the Chapter 6 due-diligence pattern and does not re-own their work.
- **Upward links.** [`ai-enablement-lead`](https://github.com/ai-workforce-curriculum/ai-enablement-lead-learning) (L45) owns the org-wide vendor framework and enterprise-commit negotiation; the team manager's registry is one input into their program view.
